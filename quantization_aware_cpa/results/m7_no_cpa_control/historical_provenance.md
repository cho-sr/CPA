## Fixed FIA and metric settings

All five historical source summaries agree on:

- FIA iterations 25,000; logging interval 5,000.
- Learning rate 0.1; Adam; cosine annealing over 25,000 steps to zero.
- Feature cosine-loss coefficient 1.0; TV coefficient 0.1; FIA seed 42.
- ImageNet-pretrained VGG-16 `IMAGENET1K_V1`, eval mode; round-0 checkpoint.
- Feature target dimension 25,088 from frozen convolutional features and
  average pooling, flattened before `classifier.0`.
- `qacpa/fia.py` computes cosine feature loss and mean absolute TV on
  ImageNet-normalized image tensors; reconstruction pixels are clamped to RGB
  `[0, 1]`. LPIPS is TorchMetrics VGG, applied to RGB rescaled to `[-1, 1]`.

FIA sets CuDNN benchmark mode, not deterministic algorithms. The seed and
initialization schedule are controlled, but bitwise rerun determinism is not
promised by the historical implementation.

## Historical matching and the no-unmixing boundary

`qacpa/alignment.py` uses Hungarian assignment maximizing absolute embedding
cosine against `S_true`, within each victim batch. Historical CPA target
preparation then applies the matched scalar/sign and absolute values before
FIA. LPIPS evaluation itself is positional; it does not run an image-LPIPS
Hungarian assignment.

M7 preselects exactly eight observation rows per batch by
`torch.randperm(4096, generator=torch.Generator().manual_seed(0 + b))[:8]`,
including any selected zero row. The same row indices apply to fp32 and 4-bit.
Only L2 row normalization is allowed. There is no centering, whitening, ICA,
unmixing, absolute value, sign correction, clipping, or truth-based row
selection. For metric comparability, the already-fixed signed targets may be
assigned to originals using the same absolute-cosine Hungarian permutation;
the evaluation permutation never changes the target sign or scale passed to
FIA. This remains oracle evaluation matching and must be labeled as such.

## Preregistered interpretation recommendations

The primary inferential claim is the conjunction that **4-bit CPA has lower
LPIPS than both 4-bit no-CPA and prior-only**. Compute the mean paired LPIPS
improvement for each of the five victim batches, then an exact one-sided
paired sign-flip test over all `2^5 = 32` batch sign assignments for each
comparison. The conjunction uses intersection-union `p = max(p_no_CPA,
p_prior)` at alpha 0.05. Its minimum attainable p-value is 1/32; do not count
the 40 images as 40 independent attack draws. This test assumes exchangeable
method labels/symmetric paired batch differences under its null. With five
batches, it is intentionally resolution-limited. fp32 is a secondary
reference and should include a sensitivity summary excluding the four
exact-source supplements.

For image counts, freeze a leave-one-victim-batch-out lower-tail rule before
viewing new results. For each candidate LPIPS `l`, use the 32 no-CPA values
from the other four batches and independently the 32 prior-only values from
those batches. For each control compute
`p_control(l) = (1 + count(control_LPIPS <= l)) / 33`; count only candidates
with `max(p_no_CPA, p_prior) <= 0.05`. At this sample size the rule requires
strictly lower LPIPS than every one of each control's 32 reference values.
Report these as **control-calibrated lower-tail successes**, along with the
separate batch-level inference. The reference-rank interpretation assumes
exchangeable reference-image difficulty; it is not proof of independent
per-image significance and does not control familywise error over 40 images.
Do not change the alpha, reference batches, tie handling, or count definition
after seeing results. This protocol may legitimately yield zero successes.
